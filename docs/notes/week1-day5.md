# День 5. ASP.NET Core API: создание проекта и первый эндпоинт

## Что узнал
- Команда `dotnet new webapi --use-controllers --framework net8.0` создаёт структуру REST API проекта с поддержкой классических контроллеров на платформе .NET 8.
- С помощью `dotnet add reference` связываются проекты внутри одного решения, что позволяет использовать общие модели (например, из `Toir.Shared`).
- Библиотека `Swashbuckle.AspNetCore` (версии 6.6.2 для .NET 8) автоматически генерирует документацию и интерактивный UI для тестирования эндпоинтов (Swagger).
- Создание обобщённого класса (Generics) `ApiResponse<T>` позволяет унифицировать все ответы сервера, приводя их к единому стандарту (Success, Data, Message, ErrorCode).

## Вопросы
1. **Зачем нужен метод `AddControllers()` в `Program.cs`?**
   Этот метод регистрирует подсистему контроллеров в контейнере зависимостей (DI), позволяя приложению находить классы с атрибутом `[ApiController]` и маршрутизировать HTTP-запросы к их методам.

2. **В чём разница между статус-кодом HTTP 200 и свойством `Success: true` в JSON?**
   Статус-код `200 OK` — это стандарт протокола HTTP, говорящий о том, что сам сетевой запрос успешно доставлен и обработан веб-сервером. Свойство `Success: true` — это кастомная внутренняя логика приложения, которая сообщает клиенту, успешно ли выполнилась конкретная бизнес-операция внутри кода.
